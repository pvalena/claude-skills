Review Skill — Future Work
==========================

1. Clarify the skill's scope vs automated PR review
   The review skill is designed for deep, structured human-directed review
   with reasoning files and draft fixes — not for automated PR triage.
   The built-in /review and /code-review commands handle the automated
   case. This skill's value is the structured process that can't be
   easily automated: sanity check -> deep read -> reasoning trail ->
   draft fixes -> double-check. Make this distinction clearer in the
   "When to Use" and Purpose sections.

2. Potential enhancements (evaluate before implementing)
   - Investigation file guidance could be expanded: when to create one
     vs not, what level of detail, how to structure for different review
     sizes (the current PR176/PR177 guidance is minimal)
   - The "Reviewing Multiple MRs" section (13 lines) is thin — could
     document the parallel agent spawning pattern more concretely
   - Phase 4 (Deepen Reasoning) is short and somewhat vague about what
     "filling in gaps" means in practice — could use an example
   - The relationship between Phase 2 (Verify) and Phase 6 (Double-Check)
     could be clarified — they overlap in intent but differ in timing

repo-config Skill
=================
Standardized per-project configuration for skills that need project-specific
parameters. Short YAML file (.claude/commit.yml or .claude/repo-config.yml)
declaring commit conventions, validation commands, line width, version-tracked
files, disabled checks. Skills read this instead of grepping CLAUDE.md.
The commit skill already checks for this config first and falls back to
CLAUDE.md discovery when absent.
